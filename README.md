## 为什么插件服优先 Paper，而不是 Spigot 或 Forge

Paper 是 Spigot 的高性能分支，兼容大部分 Bukkit 和 Spigot 插件，同时额外提供了一批优化选项。同一个插件包，在 Paper 上通常能跑，还能顺带拿到更好的 TPS 表现。

Spigot 的优势在兼容性，一些改动较深的老插件只认它。代价是性能和新特性都不如 Paper，新版本跟进也慢半拍。除非你手上有个非它不可的插件，否则没必要从 Spigot 起步。

Fabric 和 Forge 属于模组服路线，跟插件服不是一套生态。模组改的是游戏内容本身，插件是在服务端加规则和玩法。两者可以共存（比如 Hybrid 端），但排错难度会翻倍，新手别一上来就混着搞。

走 Paper 路线要准备两样东西：对应版本的 Paper 核心 jar，以及匹配的 Java 版本。新版 MC 通常要求更高的 Java，1.21.x 这个量级的版本用旧 Java 会直接启动失败，日志里会明确写出版本不符。开服前先去查一眼你要开的那个版本要求哪个 Java，比事后翻日志省事。

还有个认知要纠正：卡顿的时候加配置是最后手段，不是第一手段。视距、实体数量、刷怪频率、红石机器密度、插件本身的负载，这五项治理完再谈升级。Paper、Purpur、Pufferfish 这些核心的仓库和文档里都给了默认配置建议，照着调一遍，效果往往比从 2 核升到 4 核明显。

## 按人数和插件量选配置：三档的适用边界

社区教程给出的经验分档是这样：2 核 4G 对应 2 到 5 人轻度生存、插件少、视距别开太高；4 核 8G 对应 5 到 15 人，或者中等插件量；8G 以上对应更多玩家、更重的插件、更高视距。这套数字只能当起点，实际能带多少人取决于你装了什么。

装五个轻量工具插件和装一套 MythicMobs 加 RPG 属性加战令，同样是 4 核 8G，能带的人数能差一倍。MythicMobs 的自定义怪物带技能、带 AI 目标选择器，每个实体都在吃 tick；属性插件要在每次伤害结算时做运算；战令、图鉴这类插件还会定时扫全服数据。判断标准应该看插件在做什么，不是数了几个 jar。

小服真正需要的是稳定帧，不是峰值性能。一个 5 人服 TPS 稳定在 20，体验远好过一个 20 人服 TPS 在 15 到 20 之间反复抖。后者玩家挖方块会有延迟感，打怪会脱战，比少几个人难受得多。

磁盘单独说一句。10G 是起步不是够用，一个跑了两三个月、玩家到处跑图的主世界加下界加末地，轻松超过这个数。备份还要占一份，压缩包按版本留七份，空间需求是存档的好几倍。买之前把磁盘当独立指标看，别只盯 CPU 和内存。

计费模式上，固定计费适合长期稳定开服，动态计费适合测试服和临时活动服。动态计费要盯紧到期时间和关机策略，忘了续费被释放，存档能不能找回是另一回事。

## 插件栈怎么搭：从 MythicMobs 到 2026 年的在售生态

MythicMobs 是自定义怪物这块绕不开的插件。它能配自定义怪物的外观、名称、血量、攻击、防御、装备、移动速度、Boss 血条，能给怪物挂技能，能设刷怪点和随机生成规则，还能做自定义物品和掉落包。服主圈里说的“氪金神器”“特殊掉落”，多数是它配出来的。

它的配置按功能分文件夹：`DropTables` 放掉落包，`Items` 放自定义物品，`Mobs` 放怪物，`RandomSpawns` 放随机生成点，`Skills` 放技能，`Spawners` 放刷怪点，`SavedData` 存数据，`config.yml` 是主配置。`Mobs` 里默认带了两个文件，`ExampleMobs.yml` 是样例，`VanillaMobs.yml` 改的是服务器原版生物，动它之前想清楚。

几个实操要点。改完配置必须执行 `/mm reload` 重载，不重载经常出现改了没效果的情况，然后以为是插件坏了。刷怪点的刷新间隔单位是 tick，1 秒等于 20 tick，想 30 秒刷一只就填 600。掉落包的格式是 `[自定义物品] [数量] [掉落几率]`，配好之后绑定到怪物身上。随机生成有五个参数要理解：`MobType` 指定怪物，`Worlds` 指定世界，`Chance` 是生成几率（最高 1），`Priority` 是优先度，`Action` 里 `replace` 表示直接替换原版生物、`add` 表示追加生成。

刷怪点建议在游戏里用指令建，别直接改 `Spawners` 文件夹，手改容易造成插件读取错误。这条来自早期教程，我倾向相信它的判断：刷怪点带坐标和世界信息，格式错一个字符就整段失效。

需要提醒的是，上面这些指令语法来自较早版本的教程，MythicMobs 的细节会随版本调整。把它当机制理解，具体命令以你装的那个版本的文档为准。

2026 年的插件生态比几年前宽得多，也能看出一个规律：版本跨度极大。论坛上在更的插件里，`BTTalismans` 面向 Paper 1.18.x 到 1.21.x，做背包护符系统；`BTEconomy` 以 Spigot 1.8.8 API 编译，兼容 Bukkit、Spigot、Paper、Leaf 1.8.8 以上，还支持 Folia；`CyuAttribute` 是 RPG 属性核心，标注适配 1.16 到 26.x；`KBook` 是图鉴插件，能接 MythicMobs 的怪物击杀进度；`LT-Craft-BattlePass` 是付费战令，售价 58 元；`CustomMine` 做区域矿场，零依赖；`MiEnhance` 是 MMOItems 的装备养成扩展。也有反例，`VC-Forge` 只支持 1.12.2。

这就是插件服最容易翻车的地方：装插件前必须先对齐服务端核心和游戏版本。一个只写了 1.12.2 的插件丢进 1.21 的 Paper，结果是启动报错，严重的会直接让服务端起不来。下载页写着支持哪些版本，就按那个来，别赌。

## 开服与排错：两张清单解决八成问题

第一次启动的流程很短：启动实例生成初始文件，打开 `eula.txt` 把那一行改成 `true`，再启动一次。EULA 不同意，服务端会直接退出，日志里写得很清楚。

`server.properties` 里新手最常动的几项：`server-port=25565` 是端口，`online-mode` 控制正版验证，`motd` 是服务器列表显示的名字，`view-distance` 是视距（直接影响性能和内存），`max-players` 是人数上限，`white-list` 是白名单开关，`difficulty` 是难度。改视距这一项要克制，它是性能杀手，先从 6 到 8 起，稳定了再往上加。

**启动失败，按这个顺序查：**

1. Java 版本是否匹配游戏版本
2. 核心 jar 的文件路径是否正确
3. 目录权限够不够
4. 端口是否被占用
5. 内存参数是否超过了机器的实际可用内存

第 5 条最容易犯。给 JVM 设了 4G 最大堆，机器本身只有 4G，系统还要占一部分，结果就是启动即崩或者跑一会儿被 OOM Killer 干掉。

**能启动但朋友连不上，按这个顺序查：**

1. 实例是不是真的在运行状态
2. 地址和端口填对没有，别把面板端口当成游戏端口
3. 端口有没有对公网开放
4. 朋友的网络有没有运营商限制，让他换手机热点试一次

第 2 条是高频错误。面板本身跑在另一个端口上，游戏端口是你在 `server.properties` 里设的那个，两个数字完全不同。

## 不崩的运维三件套：备份、重启、定时指令

服务器“能跑”和“能长期跑”是两件事，差别就在这三项有没有配。

**每日定时备份。** 备份范围要包含 `world/`、`world_nether/`、`world_the_end/` 三个世界目录，再加上核心配置文件。只备份主世界，玩家在下界搭的东西丢了照样找不回来。保留最近 7 到 14 份，旧备份自动清理。不设清理策略的话，备份会把磁盘吃满，然后服务器因为写不进存档而崩掉，这个连锁反应比不备份还糟。

**定时重启。** 每天凌晨四点这类低峰时段重启一次，能释放内存碎片和插件积累的泄漏。配合“崩溃自动重启”一起开，半夜崩服没人管的情况就少了。自动重启要设冷却时间和最大重启次数，否则遇到必崩的配置错误，会变成无限重启刷日志。

**定时执行指令。** 定时广播、定时 `save-all`、定时清理掉落物，都能挂到计划任务里。掉落物堆积是低配服卡顿的常见原因之一，一个刷怪塔跑一晚上能在地上留几千个物品实体。

多实例的情况要额外注意两件事。一台机器上跑几个服，每个实例必须设清晰的内存上限，加起来不能超过物理内存，否则一个服触发 GC 会拖着其他服一起抖。端口按连续区间规划，25565、25566、25567 这样排下去；实例按“玩法-版本-用途”命名，比如 `Survival-1.21-Paper`，两个月后回来排错时你会感谢自己。

更新纪律：换核心、加插件、升版本之前先做一次快照备份。新插件先在测试实例跑 10 到 30 分钟，确认没有报错、TPS 没有明显下滑，再挪到正式服。

## 安全：下单前最该想清楚的一件事

`online-mode=false` 的时候，日志里会出现 OFFLINE 或 INSECURE MODE 这类提示。它的含义是服务器不向官方验证用户名，任何人可以用任何名字登录，包括你的管理员 ID。冒名进去之后能干的事，取决于那个人本来有多少权限。

朋友私服也建议至少开白名单，只让可信的人进来。公开服就更不用说，离线模式加无白名单，等于把服务器交给陌生人。

面板侧的基线有三条。管理员密码改到 16 位以上，含大小写、数字、符号，别把面板账号当共享账号到处发。面板尽量走 443 端口的 HTTPS，条件允许就把访问限制到固定 IP 或 VPN。多人协作时按角色分权，“能改文件”“能执行命令”“能重启实例”“能下载存档”是四类高风险权限，能拆开就拆开授予。一个只帮忙看在线人数的朋友，不需要给他下载存档的权限。

## FAQ

**2 核 4G 到底能带几个人？**
社区经验值是 2 到 5 人轻度生存、插件少、视距保守。按这个配置开，稳定；往上加人加插件，就要开始掉 TPS。想留余量，直接上 4 核 8G。

**插件服能不能和模组服混在一起？**
技术上可以，用 Hybrid 端。实际操作里排错成本会翻倍，插件和模组的报错混在一份日志里，很难判断问题出在哪边。新手先做纯插件服。

**面板端口和游戏端口怎么区分？**
面板是你登录管理界面的地址，游戏端口是 `server.properties` 里 `server-port` 的值，默认 25565。给朋友发地址时发的永远是游戏端口。

**玩着玩着开始卡，先动什么？**
先看面板监控：CPU 是不是长期接近满载，内存是不是频繁逼近上限。然后调视距，清实体（动物、掉落物、刷怪塔），再看插件负载。这三步做完还卡，才考虑升级配置。
